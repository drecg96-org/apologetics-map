# Contributing

Faith Map should make disagreements clearer, not merely accumulate apologetics talking points.

## Content rules

1. One reusable idea per node.
2. Steelman opposing views.
3. Separate claims from support.
4. Prefer graph links over duplicated explanations.
5. Mark uncertainty and disagreement honestly.
6. Distinguish scholarly consensus from theological advocacy.
7. Keep frontmatter structural and Markdown explanatory.

## Pull requests

Normal changes should go through pull requests. CI must pass before merge. The repository is intended to require review by the code owner for changes to `main`.

```bash
npm install
npm run validate
```
